## 第二部分：2–3 分钟 Demo 录制方案

### 00:00—00:20：目标与输入

**屏幕操作：** 打开已经启动的首页，侧栏预先选择四格、已验证文本 Provider 和 Recraft；粘贴预先准备的短故事，立即点击“一键生成漫画”。

**口头讲解稿：** “ComicForge AI 是一个把文本大模型和图片模型统一接入漫画制作流程的平台。这里输入故事后，系统会先生成并审查结构化分镜，再逐格调用图片模型，最后在本地完成气泡、排版和导出。我现在用 Recraft 实际生成一份四格漫画。”

**展示区域：** 故事输入、格数、文本/审查/图片 Provider 摘要和生成按钮。

**讲解重点：** 尽早启动真实生成；强调四格只是 Demo 选择，不是系统硬限制。

**不要过细：** 不展开环境变量和节点字段。

### 00:20—00:45：文本与审查

**屏幕操作：** 切到“分镜与剧本”，展示生成中的状态；若分镜已经出现，快速滚动表格。

**口头讲解稿：** “文本创作模型和剧本审查模型可以独立选择。模型输出不是直接拼接到页面，而是经过 JSON 提取、修复和 Pydantic 校验，形成故事、角色、场景、动作、对白以及每格绘图提示词。审查是否真正应用也会写入项目记录，不会把失败伪装成成功。”

**展示区域：** 状态卡、Provider/模型/耗时、分镜表格。

**讲解重点：** 结构化数据和独立审查。

**不要过细：** 不逐字段朗读 schema，不讨论每一种历史解析错误。

### 00:45—01:15：统一 Provider 架构

**屏幕操作：** 打开模型设置，依次指向文本和图片选择项，不实际切换正在执行的任务。

**口头讲解稿：** “文本和图片 Provider 是两套独立注册表，所以可以自由组合。云端方面，Recraft 已完成多次真实生图；SiliconFlow 已完成国际站鉴权和模型存在性验证，但账户余额为零，因此没有把它写成真实收费生图验收。本地方面，ComfyUI 已通过严格单图测试和无回退生成。”

**展示区域：** Provider 下拉框、状态检查按钮、能力说明。

**讲解重点：** 实现、配置、鉴权、真实生成是不同层级。

**不要过细：** 不展示 Key，不声称 OpenAI Images/Together/fal 已真实验收。

### 01:15—01:50：ComfyUI 与错误可见性

**屏幕操作：** 展示统一状态区域；可短暂展示预先截取的 ComfyUI Provider 状态或已生成项目记录，不离开应用打开 `.env`。

**口头讲解稿：** “同一图片接口也能连接本机 ComfyUI。程序会复制 API Workflow，动态替换提示词、尺寸和 seed，再提交 `/prompt`、轮询 history、从 `/view` 下载。真实 Provider 出错时会区分配置、鉴权、余额、限流、连接和轮询超时；启用 fallback 时也会明确显示实际用了哪个 Provider。”

**展示区域：** 状态卡、图片 Provider 能力或已准备的 ComfyUI 结果。

**讲解重点：** 远程 API、本地 Workflow 和可观测错误。

**不要过细：** 不讲节点 ID 全表，不现场启动或安装 ComfyUI。

### 01:50—02:20：漫画制作能力

**屏幕操作：** 展示分镜表格、页面布局选项、成品语言和单格重生成/回退控件。

**口头讲解稿：** “系统不是让图片模型直接画气泡，而是只生成每格无文字画面，再根据结构化对白在本地排字。这让台词可编辑、可切换语言，也支持传统页、网格、条漫、自定义画框、单格重生成和历史回退。当前还有多页数据结构预留，但完整多页 UI 仍是下一阶段。”

**展示区域：** 分镜表、布局摘要、成品语言、重生成与回退。

**讲解重点：** 任意格数、本地排字、可编辑性。

**不要过细：** 不逐个演示所有布局，不声称角色一致性彻底解决。

### 02:20—03:00：结果与导出

**屏幕操作：** 等生成结果出现；展示整页漫画，点击全屏并轻微滚轮缩放/拖动；切到“项目与导出”，展示 PNG/PDF/项目 JSON 下载。如果实时任务未结束，使用预先生成的 Recraft 成品并明确说明。

**口头讲解稿：** “这里是四格最终结果。每格原图、实际 Provider、模型、耗时和回退状态都保存在项目 JSON 中；标题和气泡由本地排版完成。最终可以导出 PNG 和 PDF，也能保存项目 JSON 继续编辑。这就是从故事、审查、真实生图到漫画成品的完整闭环。”

**展示区域：** 漫画画布、全屏交互、状态摘要、导出按钮。

**讲解重点：** 必须展示真实结果、无回退状态和导出。

**不要过细：** 不在结尾打开大段 JSON；只指出可追溯字段。

## 完整口播稿

“ComicForge AI 是一个把文本大模型和图片模型统一接入漫画制作流程的平台。这里输入故事后，系统会先生成并审查结构化分镜，再逐格调用图片模型，最后在本地完成气泡、排版和导出。我现在选择四格和 Recraft，开始一次真实生成。

文本创作模型和剧本审查模型可以独立选择。模型输出会经过安全 JSON 提取、修复和 Pydantic 校验，形成故事、角色、场景、动作、对白和每格绘图提示词。审查结果只有通过校验才会应用，失败原因也会明确显示。

文本和图片 Provider 使用两套独立注册表，因此可以自由组合。Recraft 已完成多次真实生图；SiliconFlow 已完成国际站鉴权和模型存在性验证，但余额为零，尚未进行真实收费生图。ComfyUI 是本地路线，已经完成严格单图和无回退生成验收。

连接 ComfyUI 时，程序会复制 API Workflow，动态替换提示词、尺寸和 seed，提交任务、轮询结果并下载到本地。无论远程还是本地，配置、鉴权、余额、限流、连接和超时错误都会分类展示；发生 fallback 时也会显示实际 Provider。

图片模型只生成无文字的单格画面，标题、对白、旁白和拟声词由程序本地绘制，所以文字可编辑、可切换语言。系统支持任意格数、多种页面布局、单格重生成和历史回退；多页结构已经预留，但完整多页 UI 还没有宣称完成。

现在展示的是最终四格漫画。全屏后可以滚轮缩放和拖动画幅；项目记录保存每格 Provider、模型、耗时、request ID、尺寸和回退状态。最后可以下载 PNG、PDF 和项目 JSON，完成从故事、审查、真实生图到漫画成品的闭环。”

## 录制失败时的备用方案

| 故障 | 现场处理 | 必须说明 |
|---|---|---|
| Recraft 网络异常 | 停止等待，切换已接通的本地 ComfyUI；先做一格或使用已准备的四格结果 | “当前云端网络异常，切换到已验收的本地路线” |
| 文本模型输出失败 | 切换 Mock 或已经验证的文本 Provider，再生成分镜 | Mock 是离线备用，不能冒充真实模型 |
| 生成超过录制时长 | 利用等待时间讲架构；到时切换到提前生成的项目 JSON/成品 | 明确这是“提前用同一流程生成的结果” |
| 某一格失败 | 展示错误分类；若已有项目，使用单格重生成 | 是否发生 fallback、实际 Provider 必须可见 |
| ComfyUI 队列或显存异常 | 清空旧队列、降低到单格/并发 1；必要时改用预生成结果 | 不把超时说成代码一定失败 |
| 导出控件异常 | 直接展示项目 `outputs/<运行目录>/comic.png` 和 `comic.pdf` | 说明文件由本次/预生成项目导出 |

录屏前应始终预先准备故事文本和一份可公开展示的生成结果；任何备用演示都不能打开 `.env`，不能暴露 API Key，也不能把 Mock 或预生成结果描述为本次实时真实请求。
